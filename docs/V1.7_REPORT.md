# AI Survival Society v1.7 — Spatial Intelligence & Physical Interaction

本文件記錄 v1.7 的架構、實際量測、驗收與限制。完整原始需求保存在 V1.7_REQUIREMENTS.txt，逐項狀態在根目錄 REQUIREMENTS_CHECKLIST.md；功能、UI 與封裝已驗收，最終 Git／Release 發佈列於文末。

## 1. Goal

The world must physically constrain behavior。延續既有 Utility AI、Living World、Story、Replay、i18n 與 Electron；沒有把 renderer 當遊戲物理，也沒有重寫整個 simulation。

## 2. Previous limitations

v1.6 的路線只有簡單 visibility blockers，移動沒有最終掃掠碰撞檢查，家具、水面、角色實體與互動容量不能可靠限制行動。互動靠半徑，登塔只是畫面高度投影。真實舊封裝與新版的同場景驗收見 [對照](V1.7_COMPARISON.md)：同 Seed、NOVA、起點、醫療目標，舊版穿過診所西牆，新版走入口至槽位。

## 3. Collision architecture

core/spatial.mjs 直接讀版本化 world-collision.json，83 個簡化矩形／圓形碰撞體涵蓋牆、柱、柵欄、家具、設備、橋欄、三個大石與深水。0.35m 角色圓做連續線段掃掠；切線接觸允許、穿透禁止。草、碎石與小型裝飾不參與 gameplay collision。碰撞體以 4m spatial hash 分桶，查詢掃掠包圍盒；12 個角色的邻居檢查仍使用有界線性迴圈。

## 4. Blender collision pipeline

實際 Blender CLI 執行 Art/Blender/generate_collision_data.py，讀原 physical_world_kit.blend，建立 SpatialMarkers collection，將 COLLIDER_、NAV_、PORTAL_、INTERACTION_ empties 的 JSON custom properties 匯出，保存可編輯 world_collision.blend。Simulation 不解析 GLB。既有美術套件保留；新增標記、少量對齊牆與樓梯，未大量重做資產。

## 5. Walkable regions

九個命名 polygon regions 覆蓋戶外與八個地標，作區域診斷、入口關係與互動定位。實际路線在島嶼範圍、坡度限制與碰撞體裁切的 0.5m 格點上求解；這是 2.5D polygon-region + grid navigation，非完整三角 navmesh／funnel。診所、避難所、補給站有正確內外動線。

## 6. Portals

八個 doorway／bridge／狹道入口包含 id、位置、宽度、fromRegion、toRegion、state、capacity、短預約。狹門容量一人，橋入口兩人。Closed／locked 阻擋；open／broken 通行。開門後 authoritative passableAt 延後 0.6s，保留鉸鏈轉開的時間，門不能關在站在門葉附近的角色身上。

## 7. Pathfinding

穩定 A* 使用固定鄰居順序、cell ID tie breaking、地表與小幅拥擠成本；先用連通分量拒絕不可達目標。視線線段平滑保留碰撞與坡度檢查。路徑保存於 agent spatial checkpoint；只在改目標、受影響動態障礙、受阻或重試時重算。Door／hazard signature 改變時，仍合法的路徑更新 signature，避免全員無條件重新規劃。

## 8. Local avoidance

偏好速度、角色連續相對掃掠、固定側移候選與穩定 ID 優先權維持至少 0.7m 中心間距。狹門低優先權角色可以退讓；入口容量只限制进入，不限制安全退回房間。三秒沒有進展會 replan，連續失敗後暫停該 action／target 45s，由 Utility 選擇其他行動。抽象撤退／探索目標投影至合法位置，接近已被別人佔用的區域終點可停止，不強擠對方。正常 gameplay 不 teleport；nearestLegal 僅用於生成點、導航目標投影與明確記錄的舊存檔遷移。

## 9. Interaction slots

26 個明確 approach／facing slots：床、醫療、箱子、radio 單容量，generator 兩個維修位。角色必須先 reserve、走到 XZ 0.18m／高度 0.2m 容差內、通過互動 LOS，再面向設備互動。Utility 使用可達路程，包括上下樓距離；不可達／無空位目標不會被當成近距離捷徑。

## 10. Reservation / occupancy

free → reserved → occupied → free 均保存在 authoritative state。前往預約 TTL 16s，已佔用持續互動每次刷新 5s；死亡、被攻擊、改目標、超時或完成即釋放。滿位可等待／下一次 Utility 改目標，不凍結角色。Portal short reservation TTL 1s，過期重新驗證。五位醫療候選、單床與雙維修位／高密度 fixture 驗證容量與釋放。

## 11. Terrain / verticality

Road 0.9、grass 1、forest 1.15、rocky 1.25、shallow water 1.4；deep water blocked。坡度閾值 1.15，標記樓梯路廊允許上下行。Watchtower 與 ruins upper level 使用顯式 x/y/z route nodes，位置 y 是 terrainHeight 上方偏移；往返與途中改目標會沿樓梯下降。沒有跳到平台。部分原始設備移到合法岸邊／上層，radio 與補給站東側動線調整，renderer 同步使用 state／collision geometry。

## 12. LOS / combat blocking

觀看、互動與攻擊共用 authoritative 簡化碰撞幾何。墙／關門／大型阻擋物遮視線；低矮設備在視線模式可忽略，互動忽略目标自身 collider，但仍檢查外牆。攻擊先檢查 line of fire，不能隔牆命中。沒有射擊遊戲級彈道或高度精細遮擋。

## 13. Persistence

未完成 checkpoint 保存 position、region、path、target、slot、portal 預約、occupancy、doors、hazards、RNG 與 cooldown。Load 會重新驗證，WeakMap 快取與 wall-clock profile 不進存檔。v1.6 未完成存檔沒有 spatial 時，nearest legal relocation 寫 migrations 與双語 SPATIAL_MIGRATED 事件。已完成舊局不做遷移，歷史座標保持原樣。

## 14. Replay

重播只讀當時 position／world／door／slot state，不重跑尋路。公開資料保留簡化 spatial schema、入口與互動狀態，以及取樣 action target／facing，省略完整 path／預約 traffic debug。向後 seek 不能洩漏未來狀態。既有每五秒取樣限制明确保留：幀間門開關或快速互動可能沒有被取樣，不能宣稱連續 frame-perfect replay。舊版歷史穿牆軌跡不會被新版尋路改寫。

## 15. Determinism

v1.7 明確改 gameplay，不要求 v1.5／v1.6 golden 相同。新 golden 比對完整 events、agents、world、winner SHA-256；避讓與 A* 沒有 wall-clock randomness。performance.now 只記量測，不參與決策或 hash。相同新版本 seed、checkpoint 與 Director 時序必須完全重現。

## 16. Benchmark

scripts/benchmark-spatial.mjs 執行 primary 1–50、holdout 1001–1050，共100個 utility-only seeds，不安排 Director／固定劇情。每 tick 檢查靜態穿透、角色重疊與重複槽位，允許新出現火／洪水中的既有角色向外逃離。門檻：每局 stuckEvents <100、replans <2000、900s 內完成；每 cohort 世界互動平均≥3且至少45局有互動、社交平均≥40、交易／結盟平均≥5、無零社交局、全滅≤15%。社會事件與世界互動一併公開，不把受阻計數當作零失敗。

最終100局全部通過 acceptance gates：零穿牆、零角色互穿、零重複佔位、零社交空白局、零世界互動空白局；單局最高 stuckEvents 76、replans 1115，均低於門檻。

## 17. Performance

最終 core 12 角色／Seed 7／60s 實測：3.806s wall time，15.77× 模擬吞吐量，1117 次尋路（293.51 calls／wall second），平均 76.43 A* nodes，p95 11.845ms，avoidance／movement 累計484.91ms。詳見 spatial-v1.7-throughput.json，可用 `node scripts/measure-spatial.mjs` 重測。本次主機同時執行其他專案與驗收工作，數字包含當時負載；這是獨立核心吞吐量，不能當成畫面 FPS。

Chrome 1920×1080／實際1×與10× run：最終實際 composer render 約27.34／27.34fps（world-browser-v1.7.json）。RAF cadence 約110／115Hz，但沒有把 RAF callback 數誤報成渲染 FPS。觀察畫面運行時最高30fps、暫停15fps，釋放 UI 輸入與其他視窗的渲染餘裕；authoritative tick 不受影響。硬體視覺驗收使用 NVIDIA RTX 3070 Ti Laptop／ANGLE D3D11。

最終 packaged Electron 同流程實測24.43／24.63fps（1×／10×），存檔恢復、實際時間前進與 Story／Replay 均通過，見 world-desktop-v1.7.json。

效能檔 spatial-v1.7-performance.json 另記完整100-seed calls、平均 A* nodes、p95 path time、avoidance/movement cost；Utility reachability 查询也計入 calls。快取／grid component／spatial hash 限制頻繁重算。計時受背景工作與硬體影響，與 deterministic facts 分離。averagePathEfficiency 是直線距離／已規劃距離的有界摘要，包含重新規劃，並非最短路徑 optimality 證明。

新增災害測試確認陷在新火災／洪水中的角色能往外撤離，但不能深入障礙或穿過實體牆。所有100 seeds 每 tick 使用不忽略靜態碰撞的獨立檢查；線段平滑也檢查中間坡面。一般 golden 驗證的效能計時只寫入忽略的 `.qa/spatial-v1.7-performance-last.json`，避免 wall-clock 檔案弄髒 Git；只有明確 `--update` 才更新受版本管理的 golden 與效能記錄。

最終 Browser／Electron 速度 fixture 在每次量測前建立新局，避免上一輪已結束造成虛假失敗，仍斷言測試前 running 與測試後 elapsed 增加。QA 的 Electron／portable 清理流程有時限，僅能終止該次啟動返回的專用 PID；不掃除使用者的瀏覽器或其他專案程序。

Portable 使用 `portable.unpackDirName=true`，每次 NSIS 啟動採獨立暫存解壓目錄，避免預設固定路徑在反覆啟動時刪除第一個實例仍在使用的檔案。QA 會在第一實例暫停時再次啟動同一個 executable／profile，確認 single-instance lock 正常退出，第一實例的 matchId／elapsed 保持一致，且 reload 後 renderer 資產仍可讀取。

## 19. Known limitations

- 2.5D 圓／軸向矩形，非 rigid body、ORCA 或 true capsule／polygon physics；視線高度近似，沒有多層室內精細遮蔽。
- 地圖範圍固定28m，格點0.5m；狹路可靠性以本版地圖与fixtures為準，新增更窄資產需重新驗收。
- Agent 鄰居對12人線性檢查，world collider 使用 hash；未為數百人規模优化。
- 重播五秒取樣，不提供 path-debug playback；已完成舊資料保留歷史動作，不捏造新版物理。
- 常態模擬仍可能受阻／改目標、全滅或少量世界互動；不保證每局治療或登塔，不用固定劇本強制事件。
- Optional Life Story distance／longest control 與 stretch capsule、flow field、ladder animation、heatmap、bulky clearance 未納入；核心穩定與可重現優先。
