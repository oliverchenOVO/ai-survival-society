# v1.1 — simulation quality and trustworthy endings

The apparent “LAST SURVIVOR / No survivors / zero statistics” failure was reproduced in the old browser build. Its open result dialog read the live world; automatic restart replaced the completed world with a running world whose winner/history did not yet exist. This does not establish that the user's particular previous match ended in extinction. The original 50-seed simulation benchmark already had social activity in every run.

## Measured comparison

Default 12-agent rules, utility only, no model calls or Director events. Seeds 1–50 were run before editing the core, at source revision `42d343248d058376311e1b85b76283f31e25fc96`. A separate 50-seed suite uses 1001–1050. Times are simulation seconds, independent of playback speed. Mean agent survival includes surviving agents up to the ending time. Missing first-event times are separately counted, never silently replaced with zero.

Substantive interactions are trade, alliance creation, cooperation, betrayal, attacks, theft and deception; repeated dialogue is excluded. Attacks are counted individually, not as distinct battles. Social events additionally include conversation. The tables measure actual executed events, not decisions or scripted quotas. Gains are in trade and mutual aid frequency, not in earlier introductions or a reduction in total environmental deaths. These finite suites are regression evidence, not a guarantee about every possible seed. Seeded inventories change the random initialization stream, so this is a comparison of the rulesets over a seed cohort, not a controlled identical-personality experiment.

*v1.0 stopped environmental processing as soon as the array contained one living agent. It could award an artificial survivor when the last two should die in the same tick. The new environmental phase resolves all living agents before deciding winner/extinction. Extinction is deliberately allowed and is not fabricated into a winner to improve a benchmark.

## Rule changes

- Safe-zone contraction waits for the first 18% of a match (75.6 seconds at the default duration). It still reaches the same final radius at the original deadline. Replay shares this rule; old archives without the grace field retain their original contraction curve.
- Nearby decision radius increases from 9 to 11 metres. Characters still walk into 2.7-metre interaction distance before an action can occur.
- Seeded initial food and medicine provide complementary needs; no character is assigned a trade, alliance or betrayal role. Trading is more attractive when surplus food can obtain missing medicine, and offers to hostile sellers are excluded.
- Starvation damage is eased from coefficient .045 to .035. Allies within 3.5 metres improve resting recovery. Mutual aid addresses hungry allies who have no food and wounded/infected allies with available medicine; every transfer consumes the donor's supplies.
- No added scheduled story events, forced social actions, minimum-event intervention, LLM or Director assistance was used in these measurements.

## Result and spectator fixes

Completed results are bound to their match ID and remain stable while continuous mode starts another world. Export captures that same complete match in a downloadable Blob, so subsequent live runs and archive pruning cannot silently change the downloaded history. Match exports can also be addressed through `/api/matches/:id/export`. The result's five metrics are explicitly island totals, rather than the winner's individual statistics. Most-social, most-trusted and mutual-aid summaries make the society visible in the ending, including agents who died.

Environmental ties now end with `outcome.kind = extinction`, no winner ID, `EXTINCTION EVENT`, a skull icon and “The island claimed everyone.” Both the banner and archive distinguish extinction. A genuine last survivor retains the winner outcome. Zero-event worlds do not invent a social MVP.

## Regression and validation

`npm test` includes the unit/server suite and both 50-seed benchmark suites. `npm run test:benchmark` reruns just the deterministic regression. Gates require no missing social events or zero-social extinctions; ≥90% runs with five substantive interactions across three pairs; ≥90% occurrence for trade/alliance/combat; ≥10% betrayal occurrence; mean first social ≤20s and substantive ≤45s; extinction ≤10%; mean trade ≥12, mutual aid ≥3.5 and substantive events ≥85. Gates were set before the holdout was examined; a failing initial holdout led to improving legitimate mutual-aid needs, not relaxing the gate. A GitHub CI template is provided at `docs/ci-regression.yml`. It is not installed as a workflow: the existing GitHub login has repository access but lacks the separate `workflow` OAuth scope. No account permissions were expanded. Local `npm test` already enforces the regression gates.

`npm run test:results` covers automatic restart, frozen result text, matching export ID/duration/statistics, simultaneous-death extinction semantics, desktop/mobile rendering and runtime errors. This UI test uses a deliberately damaged two-agent test fixture solely to exercise the ending; the production benchmark contains no such intervention. Browser plugin was not available, so Playwright Chrome was used. Full existing browser controls and replay workflows were also rerun.

The current checkout also installs `.githooks/pre-push` through the repository-local `core.hooksPath` setting. Normal local pushes run `npm test` and stop on failure. Fresh clones can opt into the same hook with `git config --local core.hooksPath .githooks`; it is not a hosted CI substitute and can be deliberately bypassed by Git's standard options.

Raw evidence: `docs/qa/social-v1.0.json`, `social-v1.1.json`, `social-holdout-v1.1.json`, `results-bug-before.json`, `results-ui.json`; screenshots `docs/images/v1.1-result.png`, `v1.1-extinction.png`, `v1.1-extinction-mobile.png`.

## Scope and remaining work

This release prioritizes simulation incentives, regression protection and correct spectator results. Existing roster, follow camera, event-focused cinema and event history remain available. New dialogue bubbles, alliance animation, death cinematics and a full historical per-agent life viewer are future work; the sampled replay is not a complete state reconstruction. Public hosting is also future work. The existing Docker deployment recipe has not been run in this environment or deployed to a public host. Model credentials remain server-side, and utility mode needs none. v1.0's optional remote-model and hosting limitations still apply.
